## Direction contract

THESIS: The threshold to Century Road is a wire dispatch arriving, not a marketing hero — the visitor watches today's date print itself in like a telegraph bulletin before the masthead resolves, refusing the generic "big background image + headline + CTA" SaaS-landing arrangement.

OWN-WORLD: Bulletin ivory (#F6F1E4) / newsroom black (#141210) per system theme, newsprint ink / ivory white text, wire-red (#C81E3A light / #E54D61 dark) reserved for the CTA only. Masthead in Oswald 600, the ticking dateline in the existing monospace dateline treatment (0.6875rem, uppercase, tracking-wider) — the exact device already used on every event card's date stamp, not a new one. Zero radius, no shadow, no gradient, hairline rules only. Photography (added after initial ship, user-requested, then user-referenced against the well-known "infinite logo carousel" pattern) is admitted as a first-time material for this system, but on the system's terms: full color is refused (One Voice Rule reserves saturation for wire-red alone) — every photo runs through `grayscale` + `contrast` — frames are separated by hairline seams (the same material language as every rule elsewhere in this system, not a card border) — and a solid, flat scrim sits between photos and text (never a gradient or blur as decoration; the one gradient in this build is a CSS edge-fade *mask*, a technical device for the marquee pattern, not a visible color gradient). A loading tile shows `bg-muted`, not `bg-background` — a flat, in-system tone that reads as "a frame waiting to develop" rather than a hole matching the page behind it — and crossfades to the photo over 700ms once it arrives; not a shimmer/skeleton animation (this system doesn't have one and this isn't the place to invent one), just an opacity transition already covered by the reduced-motion kill-switch.

STORY: The visitor understands they've reached a live archive that updates daily, not a static site — the sequence itself proves "today" is real before any content does. Behind them, three filmstrips of real photography from a genuinely different, randomly-picked day of history scroll past continuously and seamlessly, alternating direction row to row, hinting at the archive's breadth before they've clicked anything. They watch, then press "Entra" into the Mappa.

FIRST VIEWPORT: Centered column on the fixed theme background, full viewport height, no sidebar or header chrome (a true threshold, outside the app shell). A monospace dateline (today's real date, locale-formatted) types in first, alone. Then "CENTURY ROAD" resolves above it in large Oswald caps, "press archive" beneath in the label voice. A hairline rule. Then the wire-red "Entra" button fades in last, sized to the 44px touch floor. Full-bleed behind all of it: three stacked horizontal bands (each 1/3 viewport height), each a seamless infinite filmstrip drawing a distinct slice of the same photo pool (real Wikimedia images tied to real events of one randomly-picked day, not today's — see `useHistoryPhotoCarousel`), each frame carrying a compact year plate, edges soft-masked (`mask-image` with a `-webkit-mask-image` twin for Safari, which never shipped the unprefixed property). Rows alternate direction (top: left-to-right, middle: right-to-left, bottom: left-to-right — each opposite its neighbor, user-requested) and run at 18-28s per loop, staying different per row so the three never look mechanically synced. The photo pool draws 24 images per visit (8 unique per row, 16 once doubled), excluding SVGs, PNGs, and any candidate over 600px on a side (see FINISH for why) — a real day's pool of qualifying entries still runs 25-55+ after all three exclusions, measured directly against the backend, so 24 has real headroom. The seamless-loop technique: each row's track is its slice of the pool twice back to back, animated exactly ∓50% (direction per row via `animation-direction: reverse`), so the seam is invisible. Reduced motion (OS or the in-app override, read once per visit) removes the duplication and all three animations entirely: three static rows, no loop, no scroll. Below the fold, reachable by scroll: a quiet footer consolidating the app's existing data-source attributions (Wikipedia, Wikimedia Commons, OpenStreetMap/OpenFreeMap, Natural Earth, GitHub), reusing existing attribution copy; no per-photo credit UI exists with this many photos visible at once — attribution for images is a general Commons link, not per-frame.

FORM: Structural candidate 4 of 7 on the ordered grounded list for this surface (front-page splash, dateline countdown, dispatch stack, **wire ticker awakening**, archive vault threshold, two-column bulletin, quiet reading room) — dealt to the table at position 4 of the roll (dealt indices 7,6,4) and locked by the user. Seed key 3e1679c1. Seven user-requested follow-ups since: a single-photo Ken Burns crossfade (superseded, removed), a single seamless filmstrip built against a named external reference ("Seamless Infinite Logo Carousel", freefrontend.com/css-carousels/), split into three alternating-direction rows, a perceptibility/load-speed pass, a density pass raising the photo count, a reliability pass (SVG exclusion + muted-placeholder crossfade), then a page-weight pass (PNG exclusion + a 600px tile-size cap, see FINISH) after a load-speed audit found individual carousel frames running 600KB-2.3MB despite passing every existing check — all extend the locked FIRST VIEWPORT rather than reopening FORM; the world (OWN-WORLD) held through every iteration.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance. Load-speed pass: `<link rel="preconnect">` added in `index.html` for `upload.wikimedia.org`/`thumb.wikimedia.org`, `decoding="async"` throughout, `loading="lazy"` tried and reverted (defeated by the strip's continuous loop), muted-placeholder crossfade in its place. Page-weight pass (later, from a full load-speed audit against the production build): Wikipedia's own "thumbnail" field is sometimes the unscaled original verbatim when the source is already narrow enough to skip resizing — for a lossless PNG that measured 1.6-2.3MB despite passing the existing 1600px dimension cap (which only ever guarded the `originalImage` fallback in `buildImageSources`, never the `thumbnail` field itself). Two fixes in `useHistoryPhotoCarousel.ts`: exclude PNG sources outright (same off-brief logic as the SVG exclusion — Commons PNGs are almost always maps/montages/logos, not photographs), and cap any candidate (thumbnail or original) at 600px on its longest side, since these tiles only ever render at 160-224 CSS px. Along the way, found and fixed a real bug in the SVG exclusion itself: Wikimedia URLs carry a query string, so the original `/\.svg$/` regex never matched anything (`$` anchors the literal string end, which is mid-query-string, not the extension) — it had shipped and been "verified" against a pool-size count that never actually exercised the exclusion path. Disclosed limit, not fully solved: dimension alone doesn't reliably predict byte weight — one measured outlier was a 330×330 JPEG at 876KB, well under the 600px cap. The API never reports byte size, so a full guarantee would need a HEAD request per candidate before selection, which trades network round-trips for a rare, small residual risk; not worth it at this scale. Known open item, disclosed rather than silently resolved: the filmstrip's photo pool is genuinely unfiltered real history (any real Wikipedia "selected"/"events" entry with a qualifying image, from a random day) — it can surface intense subject matter (war, atrocity, named perpetrators) on the very first screen a new visitor sees, across three rows of simultaneously-visible photos. No content filter exists yet; whether one should is a product/editorial decision, not a design one, and is unresolved.
